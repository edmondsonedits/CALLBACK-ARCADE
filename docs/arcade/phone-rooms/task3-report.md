## Scope and behavior

Created `public/arcade-games/phone/{host.js,controller.js,controller.html,phone.css}` and added exactly one classic defer `../phone/host.js` script, with the matching `data-game`, to each of the seven approved game pages. Game engines, backend, catalog, QR bundle, credentials, and publishing are outside this change. Host initialization waits for DOMContentLoaded so Sumo's boot callback and deferred game modules have exposed their adapters.

The TV launcher opens a named native modal, shows the four-character code, local QR, join link/copy action, ten seats, connected names and bots, and Start/Pause/Resume/End/Back actions. Start requires a connected phone and is the only path that starts the adapter. A fresh/reloaded room remains inactive until explicit Start even if an offline game is already running. The modal collapses to an edge code/count pill, restores launcher focus, and stops pointer/keyboard events only when their targets are inside the host widgets. No routine poll starts/resumes/reconfigures a game. Adapter status is reread before every host request and before packet application, following native pause/menu/phase state. Legacy Sumo/Blind room entry controls stay hidden.

The host applies ordered inputs, deduplicates by seat/sequence, and acknowledges only successfully handled packets. Routine roster reads assign only new/reconnected/renamed seats. Independent 100ms watchdog checks clear held input after500ms and release absent seats to bots after3seconds without consuming/inventing a sequence. Each own private state receives only its own `appliedSeq`; no other-seat private fields are introduced. Host polling has one request in flight, approximately100ms during play/300ms before start, capped exponential failure delay up to2seconds, and a2.5second request timeout. Late host responses after explicit close cannot reassign seats or deliver input. Explicit successful End closes server ownership, stops the adapter, and removes the optional sessionStorage room code. Navigation pauses local input; phones then observe the backend's host-missing status.

The phone restores its own seat using a cookie-authenticated poll and public `?code=ABCD`, without issuing a duplicate join. A new player enters a code/name, and Change room returns to the form. Identity/roster names use textContent. Neither script reads/stores/logs a credential; only a public room code is placed in sessionStorage/URL. All fetches use same-origin POST JSON and cookie credentials.

Short press/release edges remain separate and ordered while requests are in flight. Only unsent axis snapshots coalesce. Accepted-but-lost responses reconcile authenticated `lastSeq` and keep later edges. Unaccepted packets retain their sequence for retry, observe bounded backoff (1second on429), and reset safely after three persistent failures. Poll and input loops each allow one in-flight request; recovery shares the same poll promise. Held axes/buttons refresh around150ms. Idle ordinary-phone polling is approximately1second, held ordinary controls350ms, and private Blind/Roller views200ms. All requests have2.5second abort timeouts; failure polling backs off to3seconds. Paused/inactive/missing-host/eliminated/finished states disable controls while polling continues for the next round. An8second local snapshot watchdog also disables input. Blur/hidden/pointer cancellation neutralize controls. Joystick pointer capture, deadzone/unit-radius axes, independent touch/key sources, keyboard fallback, safe-area responsive layouts, and reduced-motion rules are included.

## Limitations / release concerns

The DOM harness is not a browser layout/accessibility engine. Native dialog focus trapping/default button behavior, real pointer capture and multitouch, mobile portrait/landscape dimensions, physical-phone game feel, QR scanning, iframe focus behavior, and real network latency/loss require browser/device QA. Static CSS bounds and simulated interactions do not establish pixel-perfect layout or competitive timing. Measured delay is request round trip, not end-to-end action latency; product copy discloses variable latency and explicitly cautions rhythm timing. Host reload restores room ownership/seats but intentionally requires explicit Start to create the new TV simulation. Server events older than500ms may expire for safety, so delayed actions can be lost; UI does not claim competitive realtime precision.
