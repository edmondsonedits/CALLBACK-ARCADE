# Task 1 — authenticated D1 phone mailbox

Canonical games: `royal-sumo`, `royal-ballistix`, `royal-scratch-match`, `royal-roller-ruckus`, `royal-twisted`, `space-bash`, `blind-crown`.

All endpoints are same-origin **POST**, `Content-Type: application/json`, credentials via separate Secure HttpOnly SameSite=Strict host/phone cookies scoped to `/api/arcade-phone/CODE`. Room codes confer no authority. Responses are `no-store, private`. No response JSON contains credentials, hashes, or other phones' private state. Deployment migration/schema use only isolated `arcade_phone_*` tables; there is no call to party-room initialization, score, or match services.

| Endpoint | Request | Success response |
|---|---|---|
| `/api/arcade-phone/create` | `{game}` | 201 `{code,game,maxSeats:10,expiresAt,serverNow}` plus host cookie |
| `/api/arcade-phone/CODE/join` | `{name}` | 201 phone snapshot plus `restored:false`, phone cookie; existing authenticated phone returns 200 snapshot plus `restored:true` retaining its seat/name |
| `/api/arcade-phone/CODE/input` | input packet below | 200 `{accepted:true,seq,serverNow}` |
| `/api/arcade-phone/CODE/host` | `{status,privateStates?,ack?}` | 200 `{code,game,status,roster,inputs,serverNow,expiresAt}` |
| `/api/arcade-phone/CODE/poll` | `{}` | 200 own phone snapshot |
| `/api/arcade-phone/CODE/close` | `{}` | 200 `{closed:true}`, host cookie cleared; both host/phone credentials invalidated server-side |

Input packet: `{seq,x,y,buttons,plan?}`. `seq` is an integer 1..Number.MAX_SAFE_INTEGER, strictly greater than this seat's last accepted sequence; gaps are permitted. Axes are finite numbers [-1,1]. Buttons are integer bitmask 0..15. Optional `plan` is exactly `{x,y,a,locked}` with normalized x/y [0,1], a [-pi,pi], boolean locked. Unknown keys are rejected. Name is trimmed, 1..24 characters, no control characters; render using textContent.

Host status is exactly `{phase,paused,active,text}`: phase trimmed 1..40 characters, paused/active booleans, text <=160 characters. No scores or phase authority are accepted for King Prompter. Creation starts `{phase:"lobby",paused:true,active:false,text:"Waiting for host"}`. The host must send active:true and paused:false to accept inputs. Inputs while paused/inactive or without a host heartbeat within8seconds return409 `HOST_PAUSED`.

Optional `privateStates` maps keys `"0"`..`"9"` to JSON objects or null. Each object <=8192 UTF-8 bytes, depth <=6, arrays/objects <=128 members, finite numbers, no prototype keys. Sending the map replaces all private states; omitting it preserves them; send `{}` to clear them. Host responses omit this map. Phone snapshot is exactly `{code,game,seat,name,lastSeq,status,hostAlive,privateState,serverNow,expiresAt}`; own privateState defaults null. Status.paused is forced true when the host heartbeat is stale. Refresh/rejoin reads lastSeq; choose next seq >lastSeq. Polling touches phone liveness and retains seat. A disconnected phone retains its ownership credential for reconnect until close/expiry; hosts may use bots during absence.

Roster entries: `{seat,name,connected,stale,lastSeq,inputAgeMs}`. connected becomes false after3seconds without authenticated input/poll/join. stale is true after500ms without accepted input (or no input); inputAgeMs is null before first input. The host runtime must clear held controls when stale/disconnected and on pause. These flags convey mailbox state, not game scoring.

Inputs are `{seat,packet,receivedAt}` sorted by seat then sequence. Optional host `ack` maps keys `"0"`..`"9"` to highest applied sequence (integer0..Number.MAX_SAFE_INTEGER). A single D1 transaction updates heartbeat/status, removes expired/paused events and acknowledged events (`seq <= ack`), then reads roster and pending inputs. New arrivals after the transaction remain pending. Without acknowledgement, returned inputs replay; host runtime must deduplicate using each seat's highest applied seq and send that map on its next host request. Thus a lost HTTP response leaves the pending batch available for retry within its500ms safety expiry. Each seat has64 pending events; full queue returns429 `INPUT_QUEUE_FULL` with Retry-After1; retry the same sequence after host acknowledgement. Sequence validation and insertion share the transaction, preventing concurrent overwrite. Duplicate/older sequences return409 `STALE_SEQUENCE`. Press/release packets remain distinct. Events older than500ms expire for safety; host paused/inactive clears queued events. Delivery is polling with variable latency, not competitive realtime precision.

Limits: ten immutable seats0..9, six-hour room expiry, 12,000-byte request body on non-host routes using existing HTTP utility; host route alone uses an isolated streaming reader capped at96KiB, permitting ten8KiB private states. Malformed/unknown schemas400, missing JSON content415, oversized body413, missing/wrong credential401, room full409, expired/closed404, unknown route404, methods other thanPOST405 with Allow:POST, cross-origin403. Error JSON uses existing `{error:{code,message}}` envelope. Cookies never enter URL/storage/snapshot; SHA-256 hashes only in D1. Creation cleans expired/closed mailbox records without reading unrelated tables.

## Production D1 join compatibility fix

Production v66/v67 room creation and close succeeded, but fresh and concurrent joins failed. The diagnostic release exposed the concrete cause: `D1_ERROR: too many terms in compound SELECT: SQLITE_ERROR`. The ten-seat candidate list used ten `UNION ALL SELECT` terms, accepted by Node SQLite but rejected by deployed D1's compound-select limit.

Replaced only that list with `WITH candidate(seat) AS (VALUES (0), ... , (9))`. Seat selection remains one atomic INSERT SELECT with the same lowest-free-seat ordering, live-generation/expiry predicates, unique constraints, and ten-seat capacity. No migration/API/credential change. The test D1 adapter now reproduces the observed rejection of the ten-term query before executing SQLite.
