## Architecture / constraints

Use a separate authenticated D1-backed input mailbox service in this Site, not a fake WebSocket service using process memory. The TV runs the supplied deterministic/physics game, authoritative within a trusted family room; the server owns room membership, credentials, capacity, expiry and validated input routing. Existing party-game server/D1 scoring/authority is unchanged. Standalone scores are never submitted as trusted King Prompter results. Ten phones use seats0..9. Bots fill unused seats. Host stays open. Private Blind Crown plans must be individually filtered; public host render uses spectator state. Polling has variable input latency; expose measured lag honestly, do not promise competitive rhythm precision.

Auth: random host and per-seat credentials in separate Secure HttpOnly SameSite cookies scoped to room API path, hashes only in D1. Room codes/IDs confer no control. Same-origin POST, bounded bodies, strict schemas, monotonically increasing input sequence, bounded input queues, room expiry, host liveness and per-seat ownership. No token in URL, JS storage, logs or snapshot. Ten concurrent joins must allocate uniquely/atomically and eleventh fails. Host read must never touch unrelated party tables. Close invalidates all credentials. Reconnect retains same seat cookie.

Uniform input packet: `{seq:number,x:number,y:number,buttons:number,plan?:{x:number,y:number,a:number,locked:boolean}}`; x/y axes [-1,1], buttons bitmask0..15; sequential queue preserves short press/release. Blind plan normalized coordinates [0,1], angle[-pi,pi]. Host snapshots per-seat limited JSON; only that phone receives its own, no public/debug blind plan leaks. Status is bounded phase/paused/text only, no scores-authority crossing. Max10seats, room6hours, staleinput500ms neutralize, disconnectedafter3sec bot, hostheartbeat missing8sec pauses controllers.
