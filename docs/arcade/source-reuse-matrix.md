# Arcade source reuse matrix

Audit snapshot: 2026-09-27. Source repositories and their checked-out `main` snapshots were inspected; implementation must pin a commit and recheck notices before copying. This is a technical provenance screen, not a legal opinion.

## Shared findings

- Open Party Lab's [Mini-Game SDK](https://github.com/Hartwich/Open-Party-Lab/blob/main/docs/minigame-sdk.md) and [multi-repo guide](https://github.com/Hartwich/Open-Party-Lab/blob/main/docs/multi-repo-games.md) define OPL room/lifecycle/scoring/broadcast and game exports for manifest, protocol, server, host, and controller. Each package is coupled to OPL contracts; none is a drop-in King Prompter game. Only isolated rules/simulation are potential adaptation candidates.
- All 19 checked game `package.json` files declare `Apache-2.0`. Fifteen also have a root `LICENSE` containing Apache-2.0 text. Four (`card-table`, `dungeon-party`, `flatterfluff`, `schattenjagd`) have no root LICENSE in the inspected snapshot. A package metadata string alone is insufficient for copying: Card Table, Dungeon Party, and Flatterfluff remain rebuild/no-copy pending a license file or explicit permission. Schattenjagd was rebuilt with original King Prompter code and cases; no upstream material is used. The [OPL root NOTICE](https://github.com/Hartwich/Open-Party-Lab/blob/main/NOTICE.md) does not replace each game's own rights evidence.
- Every inspected game package has an optional peer dependency on `@open-party-lab/game-core@0.1.0` and a `phaser@^3.90.0` peer. `buzzwort`, `imposter`, `schaetzorama`, and `schattenjagd` additionally declare `@open-party-lab/utils@0.1.0`; `drift-racer`, `magic-arena`, and `magic-duell` also use `three@^0.184.0`. Card Table has `pngjs@^5.0.0` as a dev dependency. These are package-level direct dependencies only: transitive dependency licenses were not fully inventoried, so complete dependency compatibility remains unresolved.
- README rights notes commonly flag assets, generated media, prompts, words, or third-party references for separate review. No item-by-item asset, font, sound, prompt, word-list, or dataset clearance was established. Use King Prompter-owned content unless provenance/rights are confirmed. Explicit upstream claims are reported as claims, not independent clearance.
- License obligations for repositories with a verified root Apache-2.0 LICENSE: retain the license and copyright notices, mark modified files, preserve applicable NOTICE attributions, and check patent/trademark and dependency terms. No game-level NOTICE file was found in the inspected snapshots. Do not infer game rights from OPL's root license.

## Air Hockey source candidates and obligations

The exact simulation candidate is [`src/server/index.ts`](https://github.com/Hartwich/air-hockey/blob/main/src/server/index.ts). It includes initial puck/paddle state, normalization, serve setup, the authoritative `tick(...)` loop, wall/goal/paddle collisions, scoring, and paddle-intent handling. [`src/protocol.ts`](https://github.com/Hartwich/air-hockey/blob/main/src/protocol.ts) defines protocol/input state but is not the simulation. The package manifest maps the `./server` export to compiled `dist/server/index.js`, sourced from `src/server/index.ts`; it also declares optional `@open-party-lab/game-core@0.1.0` and `phaser@^3.90.0` peers. The source imports runtime helpers from game-core, so port/adaptation must remove that coupling and be reviewed against the chosen King Prompter authoritative server boundary.

The repo's root [`LICENSE`](https://github.com/Hartwich/air-hockey/blob/main/LICENSE) is Apache-2.0; no game-level `NOTICE` was found. If code is copied, retain the license/copyright notices, identify modified files, preserve any applicable NOTICE attributions, and review dependency terms. The README marks the game alpha, with physics, touch balance, and match-end polish outstanding. Do not copy table/puck art, sound, screenshots, or generated media absent item-level provenance.

## Audit limits / reuse rule

This pass verified each catalog game's repository, package manifest and license declaration, inspected root LICENSE presence/text, and checked direct dependency/runtime coupling and repository asset/data notices. It did not complete a transitive dependency license audit or independently validate each media/content item's provenance. Thus this is not a full legal or asset audit. No code or media was copied. Any later code adaptation must pin the source commit, recheck exact file coverage and notices, inventory transitive dependency licenses, and keep unverified assets/data out of King Prompter.
